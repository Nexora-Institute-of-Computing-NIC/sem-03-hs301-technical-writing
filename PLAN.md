# HS301 — Technical Writing — PLAN

**Semester:** 3 · **Credits:** 2 · **Level:** Intermediate
**Theory:** 30 hrs · **Lab:** 15 hrs · **Tools:** Markdown, LaTeX (optional), Grammarly, Hemingway

## Syllabus

### Unit 1 — Foundations of Technical Writing (6 lectures)
1. What technical writing is — precision, clarity, audience
2. Audience analysis — expert, peer, learner, decision-maker
3. Plain English principles
4. Active vs passive voice
5. Conciseness — cutting without losing meaning
6. Common writing pitfalls — jargon, hedging, nominalisations

### Unit 2 — Structure and Document Types (6 lectures)
1. Paragraph structure — topic sentence, support, transition
2. Document structure — title, abstract, sections, conclusion
3. Reports — technical report structure
4. Proposals — how they differ from reports
5. User guides and tutorials — task-oriented writing
6. API documentation — reference vs tutorial vs guide

### Unit 3 — Writing for Software (6 lectures)
1. README files — what they need and why
2. Commit messages — the conventional commit format
3. Pull request descriptions — context, changes, testing
4. Issue reports — reproducible bug reports
5. Code comments — when they help, when they harm
6. Docstrings and API reference conventions

### Unit 4 — Visuals, Formatting and Markdown (6 lectures)
1. Markdown essentials — headings, lists, links, code
2. Tables and diagrams — when they help
3. Screenshots and captions
4. Code snippets — syntax highlighting, line numbers, output
5. Callouts — notes, warnings, tips
6. Common formatting errors

### Unit 5 — Editing, Review, and Publication (6 lectures)
1. Self-editing — read aloud, cut ruthlessly
2. Peer review — giving and receiving feedback
3. Grammar and style tools — what they miss
4. Plagiarism and citation — APA, IEEE, MLA
5. Publishing — GitHub Pages, wikis, blogs
6. Writing for an international audience

## Practical Labs (15)

1. Rewrite a badly written paragraph — clarity drill
2. Audience-shift exercise — same content for three audiences
3. Write a README for a real project
4. Write a commit message log — 10 commits
5. Write a PR description for a hypothetical change
6. Write a bug report — reproducible, minimal
7. Convert a report into a blog post
8. Markdown typesetting — build a README from scratch
9. Add tables and diagrams to a document
10. Write API documentation for a small module
11. Peer review — critique a classmate's README
12. Edit your own README after review
13. Grammar and readability analysis with a tool
14. Cite three sources in IEEE format
15. Publish a doc on GitHub Pages

## Assignments

1. Audience analysis and rewrite
2. README + commit messages + PR description for a real repo
3. Bug report and issue templates
4. API documentation with examples
5. Published documentation site
